# July 2026 Security & Quality Audit Report

This report documents the two-stage project audit conducted in July 2026, covering **bug remediation** and **security hardening**.

**Audit Results:** 16 confirmed software bugs + 10 quality warnings in Stage 1; 2 exploitable security vulnerabilities + 8 weaknesses in Stage 2. All issues were fully resolved, except for one converted into a user-configurable option and two accepted risks documented with security trade-offs.

---

## Audit Methodology

Audit findings were established through active empirical verification rather than passive code inspection. For each vulnerability hypothesis, an automated test probe was written to **reproduce the issue against live application components** using isolated temporary `HOME` directories and SQLite database fixtures. These test probes remain in the repository as regression and security test suites:

| Suite | Purpose |
|---|---|
| `backend/tests/test_regressions.py` | 27 test cases covering identified software bugs |
| `backend/tests/test_security.py` | 12 attack vectors probing application defenses |
| `backend/tests/test_all.py` | Expanded end-to-end integration test suite |

The test suites exit with status code 1 if a defense mechanism is weakened or bypassed, providing automated verification in CI pipelines.

## Stage 1 — Bug Remediation & Quality Fixes

### Critical Defect Fixes

**Stored XSS via Malicious Filenames with Local API Privileges:**
`escapeHtml()` previously converted DOM text nodes (`textContent → innerHTML`), escaping `< > &` but **failing to escape quotation marks**. The output was interpolated directly inside HTML attribute strings (e.g., `title="${escapeHtml(node.path)}"` in the Disk Space Analyzer). An attacker could download a folder named `x" onmouseover="...` to break out of attribute boundaries and execute arbitrary JavaScript under Martix's origin, enabling full access to local API endpoints such as `/api/disk/delete`.
→ **Fix:** `escapeHtml()` now explicitly escapes `"`, `'`, and `` ` `` characters.

**Unrestricted Deletions in `/api/disk/delete`:**
The endpoint accepted arbitrary file paths under `~` and executed recursive `shutil.rmtree()` calls without verifying whether target paths originated from previous scan operations, lacking both trash routing and confirmation.
→ **Fix:** Protected directories now return HTTP 403 Forbidden, deletions route to restorable trash, and operations on directories containing >25 files require explicit user confirmation.

**Data Deletion Side Effects on App Initialization:**
Instantiating Flask application instances via `create_app()` spawned background maintenance threads that executed `run_maintenance_cleanup()`. Importing application modules inadvertently deleted user files meeting age thresholds and duplicated scheduler startup tasks.
→ **Fix:** Initialization side effects were removed. The background task scheduler now waits a full interval before its first cleanup run.

**Uninstaller Process Self-Termination:**
Running `pkill -f martix` in `uninstaller.py` matched command line strings containing `martix`, including the uninstaller's own invocation (`python3 /.../martix/uninstaller.py`). The uninstaller terminated prematurely before cleaning up desktop shortcuts, autostart entries, and systemd services.
→ **Fix:** Process termination now targets specific server entrypoint file paths while explicitly ignoring its own PID and parent PID.

### Data Integrity & Operations

- **Non-Restorable Archive Extractions:** Undoing an archive extraction previously deleted original compressed archives with `unlink()` and renamed extracted folders to `archive.zip`, creating directories with file extensions. Archives are now preserved, move actions are logged as reversible, and extractions are logged as non-reversible events.
- **Misleading Undo History Entries:** Maintenance cleanup rows logged `destination="DELETED"` as a path, causing `undo_move` to check relative `Path("DELETED").exists()`. Added the `moves_log.undoable` column; non-reversible rows now hide Undo controls in the UI and return HTTP 409 Conflict with descriptive error details via the REST API.
- **Unsafe Maintenance Cleanups:** Maintenance operations previously deleted dotfiles directly without trash routing, leaving empty folder structures behind. Cleanups now enforce mandatory trash routing, skip hidden files/protected paths, and clean up empty parent directories.

### Classification Engine Fixes

- **`UNIQUE(extension)` Schema Constraint Bug:** Unique constraints on `rules.extension` caused new rules for existing extensions to overwrite previous entries silently via `ON CONFLICT DO UPDATE`. This prevented defining distinct rules for identical file types (e.g. separate rules for invoice vs. contract PDFs). Removed unique index constraints, added the `priority` column, implemented UI drag-and-drop reordering, and exposed `PATCH /api/rules/<id>` and `POST /api/rules/reorder` endpoints.
- **Unarchived File Edge Cases:**
  - `is_temporary_download_file` performed substring searches for `.part`, causing legitimate files (e.g., `movie.part1.rar`, `data.partition.csv`) to be treated as incomplete downloads.
  - `is_file_in_use` opened files in `r+b` mode, raising `PermissionError` on read-only files and marking them as in-use, causing 5-minute watcher timeout delays.
- **DOCX Content Extraction Failures:** Reading 20,000 bytes of `document.xml` caused truncated XML strings and parsing failures (`ET.fromstring` errors). Implemented an incremental streaming XML parser using `defusedxml`.
- **Condition & Pattern Fixes:**
  - Added support for `gte` and `lte` operators in API validation schemas.
  - Resolved `content not_contains` matching binary files by checking extractability status.
  - Prevented dynamic renaming patterns with empty placeholders from creating hidden files (`.pdf`) or empty paths.
  - Added monitored folder checks to `is_destination_or_reserved_dir` to prevent Martix from moving folders actively under monitoring.

### Performance & Stability

- **Archive Bomb Protection:** Implemented resource limits (size, ratio, entry count, free space) during extraction.
- **Disk Analyzer Optimization:** Replaced unbounded recursion with an iterative stack accumulator for tree depths below `max_depth`, reducing stack frame consumption from 60 levels to 4 frames. Added time budget limits and partial scan indicators.
- **Database Query Reduction:** Cached database schema checks once per process, reducing setting query execution from 10 SQL statements to 3. Rule loading was optimized to execute once per sweep cycle.
- **Scheduler CPU Optimization:** Eliminated 0.5-second polling loops in the scheduler thread, eliminating 172,800 unnecessary daily CPU wakeups.
- **Watcher Thread Optimization:** Deferred worker thread pool creation to on-demand execution rather than module import.
- **Windows Notification Fix:** Replaced blocking modal `MessageBox` calls per organized file with non-blocking native system toast notifications.
- **Code Cleanup:** Removed unreferenced functions (`_get_scan_dirs`, `_find_all_files`, `_scan_duplicates`, `classifier.check_conditions`).

### Configurable Behavior

- **Non-Recursive Watcher Defaults:** Directory monitoring defaults to single-level inspection to prevent disassembling nested directories during transfer. Added the `watch_recursive` setting (disabled by default) for users requiring recursive directory monitoring.

## Stage 2 — Security Vulnerability Audit

### Exploitable Vulnerabilities Fixed

**Server-Side Request Forgery (SSRF) in `/api/llm/test`:**
The test endpoint issued outbound HTTP requests from the server to user-supplied URLs without destination restrictions, returning full response bodies. This allowed attackers to probe open ports across localhost and internal network interfaces.
→ **Fix:** Implemented `security.is_loopback_url()`, restricting outbound targets strictly to loopback IP literals (`127.0.0.1`, `::1`) or `localhost`. Domain names are explicitly rejected to prevent DNS rebinding attacks.

**Information Disclosure via Directory Browsing in `/api/browse`:**
The directory browser endpoint permitted listing sensitive user directories (e.g. `~/.ssh`), exposing private key file names.
→ **Fix:** Protected directories are hidden from directory listings, and explicit access attempts return HTTP 403 Forbidden.

### Hardened Defenses

| Weakness | Resolution |
|---|---|
| Missing Content-Security-Policy & Frame Headers | Implemented strict CSP disallowing external resources alongside `X-Frame-Options: DENY` |
| Unvalidated `LLM_URL` Target Addresses | Validates target endpoints as loopback addresses on every invocation |
| Image Decompression Bombs (OCR/EXIF) | Enforced `MAX_IMAGE_PIXELS` (64 Mpx) and converted decompression warnings to exceptions |
| Unbounded PDF File Processing | Applied a strict 256 MB file size limit prior to document parsing |
| Argument Injection in `notify-send` | Prepended `--` argument separators before user input parameters |
| Unbounded Duplicate File Scans | Enforced caps of 200,000 files and 120-second execution timeouts |

### Verified Defenses

- **Path Traversal Protection:** Confirmed `send_from_directory` uses `safe_join` to block traversal attacks.
- **Symlink Escape Protection:** Confirmed `resolve_safe_path` resolves target symlinks prior to evaluating boundary containment.

### Accepted Risks & Design Trade-offs

Documented in [security.md](security.md#4-accepted-risks):
1. **API Token Storage in `localStorage`:** Mitigated by restrictive Content-Security-Policy headers.
2. **Acceptance of Requests Without `Origin` Headers:** Standard behavior for local REST APIs; mitigated by `MARTIX_TOKEN` requirement when exposing network interfaces.

## Data Migration Verification

Automatic database migration logic (`db._migrate()`) runs idempotently on startup:

- `rules`: Removes unique constraints on `extension` and adds `priority`. Existing rules are preserved.
- `moves_log`: Adds `undoable` column, marking historical maintenance and archive extraction records as non-reversible.

Migration verified against active production databases without data loss.

Dependencies added: `Send2Trash` (native desktop trash support) and `defusedxml` (hardened XML stream parsing).
